## Как читать карту

Карта построена на четырёх формах, чтобы агент видел систему по одной строке, а
не по сотне прочитанных строк кода:

1. **Граф конвейера** — порядок исполнения систем за один кадр/день/вход: кто
   кого зовёт, что читает, что пишет.
2. **Матрица доступа** — система → читает / пишет / инвариант / сложность.
   Побочные эффекты видны в одной строке.
3. **Паспорт плоской памяти** — каждый буфер: тип элемента, кап, владелец,
   ЕДИНАЯ ДВЕРЬ чтения и записи, адресация, число сырых доступов мимо двери.
   Сырой доступ к буферу мимо двери — дефект ревью.
4. **Реестр правды и расхождений** — вердикт по подсистемам с нарядом.

Перепись 2026-09-25 (сессия M-107) выполнена по коду одиннадцатью срезами
(рождение мира, поля, дневной тик, AI-свип, энтити и каталоги, состояние/сейв/
шина, стык двух миров, тик субмира, рождение клетки, рендер, кадр приложения) с
`rg`-счётами в каждой строке. Числа «на g++ 13.3/libstdc++» получены пробником
на этой машине; сборка владельца — macOS/libc++, см. §I.10 про `std::string`.

M-91 частично; остальное — наряда нет.

**⚠ `std::string` ДЕЛАЕТ РАЗМЕРЫ ЗАВИСИМЫМИ ОТ БИБЛИОТЕКИ.** На g++ 13.3 /
libstdc++ (эта машина): `sizeof(std::string) = 32`, `sizeof(Landmark) = 42408`,
