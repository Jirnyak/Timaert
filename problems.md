# История миграции на Vulkan (Проблемы и Решения)

## Что делалось:
Продолжался перевод движка с OpenGL на Vulkan (Фаза B). В процессе тестирования начались краши при запуске игры.

## Хронология проблем и крашей:

### 1. Краш: EXC_BAD_ACCESS в mvkUpdateDescriptorSets
Ситуация: Сразу после загрузки атласа paperdoll (на CPU) происходил краш в MoltenVK по нулевому адресу.
Причина: Функция ImGui_ImplVulkan_AddTexture возвращала нулевой VkDescriptorSet, который затем передавался в vkUpdateDescriptorSets. Это происходило потому что:
1. ImGui_ImplVulkan_NewFrame() вызывался *после* acquire_frame() и begin_render_pass().
2. Если текстура шрифтов ImGui еще не была создана, NewFrame() пытался её создать (вызывая vkQueueSubmit), пока главный командный буфер находился в режиме записи активного рендер-пасса. MoltenVK на macOS с этим плохо справлялся.

Как фиксилось:
1. Вызов ImGui_ImplVulkan_CreateFontsTexture() добавлен явно в boot_imgui() при старте игры, до начала каких-либо кадров.
2. ImGui::NewFrame() и связанные вызовы перенесены *до* acquire_frame().
3. Добавлен коллбек CheckVkResultFn для отлова ошибок Vulkan.
4. Добавлен цикл предзагрузки всех базовых спрайтов при старте игры (чтобы текстуры не создавались лениво во время отрисовки кадра).
5. Размер пула дескрипторов увеличен с 64 до 256.

---

### 2. Новый краш: VK_ERROR_OUT_OF_POOL_MEMORY (-1000069000)
Ситуация (текущая): После исправления первого краша игра пошла дальше и начала загружать текстуры для paperdoll. В логах видно создание сотен текстур размером 48x48.
Как только суммарное количество дескрипторов достигает лимита пула (256 штук — 1 шрифт + 11 спрайтов + 244 текстуры paperdoll), возникает ошибка -1000069000 (VK_ERROR_OUT_OF_POOL_MEMORY).

ImGui_ImplVulkan_AddTexture вызывает vkAllocateDescriptorSets, который возвращает ошибку нехватки памяти в пуле. Код ImGui логирует её, но продолжает выполнение, возвращая нулевой дескриптор, что снова приводит к EXC_BAD_ACCESS в mvkUpdateDescriptorSets.

Архитектурная проблема:
Система paperdoll создает отдельный Vulkan-объект текстуры (VkImage, VkImageView, VkSampler и выделяет дескриптор) для *каждого* кадра анимации *каждого* персонажа на экране (48x48 пикселей). При загрузке титульного экрана запрашивается более 244 таких текстур. 
Каждое создание текстуры (create_rgba8) включает в себя создание пула команд, аллокацию буфера команд, барьеры, копирование, сабмит в очередь и жесткую синхронизацию (vkWaitForFences), что вызывает огромные задержки и мгновенно исчерпывает пул дескрипторов.

## Текущий статус
Игра стабильно крашится при загрузке титульного экрана из-за исчерпания пула дескрипторов (maxSets=256).

## Следующие шаги для фикса:
1. Быстрый фикс (костыль): Увеличить maxSets в VkDescriptorPoolCreateInfo и размер пула для VK_DESCRIPTOR_TYPE_COMBINED_IMAGE_SAMPLER с 256 до, например, 4096. Это позволит игре запуститься.
2. Правильный фикс (Фаза C): Переделать рендеринг paperdoll. Вместо создания тысяч крошечных текстур, нужно:
   - Использовать единый текстурный атлас для сгенерированных кадров.
   - Либо использовать общий сэмплер для всех текстур.
   - Батчить загрузку данных (отложенная загрузка текстур через один общий staging buffer).

### 3. Баг: Bus Error / EXC_BAD_ACCESS при заходе в субмир
Ситуация: При переходе в субмир (Release-сборка) игра падала с ошибкой `zsh: bus error ./build/timaert`. В ASan-сборке падение происходило сразу со стеком, ведущим в `ImageIO` (`IIO_Reader::callGetImageCount`) при инициализации `[NSCursor(InvisibleCursor) invisibleCursor]`.

Причина: Это аппаратный баг/ложное срабатывание, возникающее на стыке macOS (Apple Silicon) и SDL2:
1. При переходе в 3D-режим (субмир) для управления камерой вызывался `SDL_SetRelativeMouseMode(SDL_TRUE)`.
2. Библиотека SDL под капотом прятала курсор, передавая в macOS (`NSCursor`) хардкодный микро-GIF размером 43 байта (`cursor_data`).
3. Маковский фреймворк `ImageIO` использует агрессивные векторные инструкции (по 16 байт) для парсинга картинок. Если эти 43 байта в памяти из-за ASLR (рандомизации адресов) попадали ровно в конец страницы памяти (page boundary), векторное чтение вылезало в неразмеченную область, генерируя `Bus error`.
4. В сборке с ASan это приводило к 100% крашу `DEADLYSIGNAL`, так как санитайзер ловил выход за границу (красную зону) 43-байтового буфера.

Как фиксилось:
1. В `src/app/main.cpp` полностью отключен вызов `SDL_SetRelativeMouseMode` для платформы macOS (`#if defined(__APPLE__)`).
2. Взамен реализована ручная эмуляция режима: мы создаем полностью прозрачный `SDL_Surface` (16x16) и устанавливаем его как курсор через `SDL_CreateColorCursor`. Это полностью обходит багнутый внутренний `invisibleCursor` в SDL/Cocoa.
3. Чтобы мышь не упиралась в края экрана при вращении камеры, добавлено принудительное возвращение курсора в центр экрана (`SDL_WarpMouseInWindow`) при регистрации `SDL_MOUSEMOTION`.
