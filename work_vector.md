## Вывод

Фундаментально сломано три вещи, и все три — не баги, а отсутствующие модели.
**Первая:** макромир состоит из двух симуляций — поселенческой экономики и
передвижения NPC, — которые не разделяют ни одной строки состояния: крестьяне
«работают» таймером, караваны ходят пустыми, отношения фракций заморожены с
boot, и всё, что ты назвал недостающим (войны, лорды, культы, царь-крестьянин,
грабежи), лежит ровно в этом зазоре — их некуда воткнуть, пока зазор не закрыт
моделью «работа = перенос ресурса сущностью». **Вторая:** шина событий — на
деле потиковый буфер с нулём подписчиков в проде и 15 мёртвыми тегами из 40;
квесты, которые должны спавнить врагов, эмитят событие в пустоту. Пока шина не
станет честной (в любую из двух сторон), контекстные квесты и генератор
историй строить не на чем. **Третья:** боевой урон не имеет модели — пять
несинхронных мест вычитания hp, ноль митигации (ни брони, ни крита, ни
уклонения), четыре несовместимых правила враждебности; сюда же упирается
экипировка: надевать предмет некуда, потому что удару нечего модифицировать.
Всё остальное — включая размер main.cpp (60 % которого — смоук-харнесс),
рукописные дистанции в 22 файлах и мёртвые каноничные функции при живых
самоделках в UI — важная, но косметика: она замедляет работу, а не блокирует
контент.

Принятые решения владельца, на которых стоит этот вектор: атрибутов ровно 16
(po2, показываем только имеющие формулу); инвентарь 16×16 = 256 слотов;
RNG-контракт уже починен в этой сессии (мир seed 12345 перебазирован).

## 1. Макро-модель: работа = перенос ресурса сущностью  [XL]

**Что сейчас.** `gather_resources(eco, population)` творит ресурсы из
`sqrt(population)`; NPC-дровосек ходит к дереву и обратно, не меняя мир; тот
самый слой деревьев с `set_tree_count` (построенный ИМЕННО под лесорубов)
из npc_ai не трогается. Караваны не несут груза. Бандиты не знают ни о ком,
кроме игрока. NPC не платят стоимость местности (ходят по океану).

**Объект модели:** «работа» — перенос количества ресурса между двумя
хранилищами, выполняемый сущностью за время. Инвариант: **ресурс сохраняется**
(создаётся только в источниках-месторождениях, уничтожается только в
потреблении); никакая формула не творит товар из населения напрямую.
Предельные случаи: крестьянин с корзиной и караван с обозом — одна и та же
работа с разными числами; грабёж — та же работа с чужим хранилищем-источником
и враждебной сущностью-исполнителем.

- **Вариант A — сущности становятся экономикой** (честный, дорогой):
  производство поселения = сумма завершённых работ его жителей; woodcutter
  реально декрементирует tree count и инкрементирует склад. Плюс: мир честен,
  грабёж каравана автоматически бьёт по экономике, «царь-крестьянин» — просто
  сущность с работой. Минус: баланс придётся перекалибровать с нуля; для
  тысяч NPC нужна дешёвая запись «работа завершена» (агрегатами, не
  потиково). Объём XL.
- **Вариант B — экономика остаётся формулой, сущности — её курьеры**:
  формула производит, но ДОСТАВКА (деревня→город, город→город) идёт только
  телами; убил караван — груз не доехал. Плюс: меньше перекалибровки,
  сразу даёт бандитам добычу и игроку перехват. Минус: производство всё ещё
  фикция, лесоруб так и не рубит. Объём L.
- **Вариант C — гибрид по ресурсам**: дерево/руда — честные (по слоям,
  инфраструктура есть), зерно/товары — формулой до лучших времён. Объём L,
  путь к A по одной строке таблицы ресурсов.

Зависимости: работа №2 (торговая сеть) — её лучше чинить внутри этой модели;
NPC-стоимость местности (один закон movement_cost на всех — сейчас только
игрок) — сюда же. Отношения фракций получают первый живой вход (грабёж =
событие отношений) — см. №3.

## 2. Торговая сеть: одна работа, а не три полупочинки  [M]

Три доказанных дефекта одной системы (audit.md II.4): (а) деревни и поселения
нумеруются каждые от нуля, резолвер прибытия ищет сначала по поселениям —
выручка деревенского экспорта зачисляется чужому городу, деревни вечно нищие;
(б) дистанция торговли плоская на торе — пары через шов не торгуют никогда
(нарушение инварианта тороидальности); (в) гарнизоны растут по +10/день без
стока и на ~820-й день молча валят сохранение целиком (kMaxSoldiers=8192).

**Решение владельца, которое здесь нужно:** кодировка единого ID
(варианты: один сквозной счётчик на оба списка; tagged id — старший бит
«деревня»; ссылка указателем/индексом типа+индекса). Всё остальное —
механика: тор-метрика из core/torus.h, сток гарнизона (кап по популяции
или смертность/роспуск). Тест-первый для каждого из трёх. Делать ДО или
ВМЕСТЕ с №1 — если выбран вариант B/C, маршруты становятся телами и резолвер
переписывается всё равно.

## 4. Модель урона и попадания  [L]

**Что сейчас.** hp вычитают 5 мест с разошедшимися протоколами смерти (плюс
3 смоук-копии); митигации нет вовсе; crit вычислен и не читается; 4 правила
враждебности; меч игрока бьёт ближайшее НЕ-игрокское тело без фракции и без
body_radius (тролль и лягушка рубятся с одной дистанции — недобитый §18);
sight — колонка, которую не заполняет ни одна строка (у всех 200);
спелл-контакт O(P·N) при готовой сетке battlePick_ в том же тике.

**Объект модели:** удар. `apply_damage(reg, target, source, amount, kind)` —
ЕДИНСТВЕННАЯ дверь: она и только она вычитает hp, ставит
LastHit/HitFlash/DamageFx/Dead, эмитит NpcDeath. Инвариант: смерть от любого
оружия неотличима по протоколу; XP-исключения (гравитация) — параметр, не
пропуск компонента. Митигация — вторым шагом внутри той же двери:
`amount' = f(amount, target.defense…)`, где f для существа без брони — тождество
(предельный случай, не ветка). Крит — там же (lck наконец читается). Сюда же:
меле игрока читает body_radius (как прицел и снаряды уже делают) и целится по
ВРАЖДЕБНОСТИ, а не по «не-игрок»; враждебность сводится к двум правилам
(бинарная маска battle + непрерывный stance ВЫВОДИТСЯ из неё); спелл-контакт
переезжает на battlePick_.

Зависимость: экипировка (№5) вешает модификаторы именно на эту дверь —
поэтому №4 фундаментальнее №5. Ещё здесь: kill-rep исключения
(wildlife/demons/bandits strcmp) → колонка реестра фракций «убийство не
преступление».

## 6. Данжи и интерьеры  [XL, дизайн-решение раньше кода]

Сейчас нуль: ни дверей, ни входов, ни подземелий; города — экстерьерные
коробки; единственный глагол взаимодействия — «лутануть труп». Твоё «как
спец-субмир наверное?» — варианты модели:

- **A. Спец-субмир** (отдельный контекст входа, как вход в клетку макро):
  данж = субмир с собственным генератором и CellContext от ландмарка.
  Плюс: вся машинерия входа/выхода и 3×3 переиспользуется (окно 1×1 или
  3×3 с глухими соседями); сохраняет правило «клетка — чистая функция
  контекста». Минус: переключение мира = загрузка.
- **B. Подземный слой того же окна** (z-уровни в существующем 3×3): вход —
  дырка в полу. Плюс: бесшовно; минус: ломает «2D-генерация, 3D-симуляция»
  (генерация станет слоистой), дороже всего по инвариантам §15.
- **C. Интерьер-модули поверх поверхности** (M&M-style: дом = телепорт в
  бокс на краю карты того же субмира). Плюс: дёшево, двери городов и данжи
  решаются одним механизмом; минус: наименее «честно».

Рекомендация: A для данжей + C для интерьеров зданий — оба переиспользуют
существующее, и «система не зависит от геометрии этажа» соблюдается.
Зависимости: коллизия уже есть (sub/collide.h); нужен глагол «войти»
(interact сейчас знает только трупы).
